БЕСКОНТАКТНОЕ ЗАСЕЛЕНИЕ: TELEGRAM-БОТ, N8N И УМНЫЙ ЗАМОК (DOCKER COMPOSE, POSTGRESQL, CLOUDFLARE TUNNEL)
Эпизод 44. Канал: @ByteAutomate_AI

ЧТО ЭТО
Гость перед заездом отправляет в Telegram-бот фото паспорта, селфи и слово «согласен». Сценарий n8n сохраняет сканы на зашифрованный том вашего сервера, записывает согласие с версией оферты в PostgreSQL, создаёт разовый пин-код и отправляет его на умный замок и гостю. Без абонентской платы за сервис: платите за сервер и замок.

В АРХИВЕ
- docker-compose.yml: PostgreSQL 16, n8n, cloudflared (Cloudflare Tunnel); постоянные тома pg_data и n8n_data;
- .env.example: пример настроек (пароль базы, ключ шифрования n8n, домен, папка сканов, токен туннеля);
- init.sql: таблицы guests, consents, access_log;
- checkin_workflow.json: сценарий n8n (17 узлов; идентификаторы подключений пустые);
- backup.sh: резервная копия (дамп PostgreSQL и архив настроек);
- Инструкция.txt: этот файл.

ВАЖНО ДО ЗАПУСКА (честные ограничения)
1. Автор стек на живом сервере и замке не запускал. Теги образов (n8n, cloudflared указаны как latest), имя переменной N8N_RESTRICT_FILE_ACCESS_TO, узлы Telegram, Postgres и чтение/запись файла в вашей версии n8n сверьте с официальной документацией. После первого успешного запуска закрепите версии образов.
2. Замок: узел «Отправить код на замок» это заглушка. Адрес, заголовок авторизации и тело запроса зависят от API вашей модели. Поддерживает ли замок разовые коды со сроком действия, проверьте у производителя. Токен замка лучше хранить в учётных данных n8n, а не в тексте узла.
3. Персональные данные: паспорт и селфи это персональные данные. Папка SCANS_DIR должна лежать на зашифрованном томе (LUKS или шифрование диска). Не пересылайте сканы в публичные чаты. Порядок обработки персональных данных по 152-ФЗ, срок хранения и текст согласия проверьте у юриста; этот набор не юридическая консультация. Автор формулировку закона по первоисточнику не сверял.
4. Оферта: текст оферты и ссылку для гостя готовите вы (в сценарии версия оферты v1 записывается при согласии).
5. Пин-код: создаётся внутри сценария случайным числом. Доступность функции crypto в Code-узле вашей версии n8n проверьте; иначе замените на другой генератор.
6. Срок пина берётся из поля checkout_at таблицы guests; если оно пустое, срок равен суткам. Заполняйте checkout_at по брони.
7. Цены облачных сервисов заселения (6000–10000 ₽ в месяц) это оценка, не замер; тарифы не сверялись.
8. Бесплатный Cloudflare Tunnel: условия и лимиты проверяйте на сайте Cloudflare на момент настройки.
9. Резервный мастер-код замка и бэкап базы обязательны: при обрыве сети замок должен открываться без интернета. Правило 3-2-1: 3 копии, 2 носителя, 1 вне сервера; не удаляйте оригиналы, пока восстановление не проверено.

ШАГ 1. СЕРВЕР
Нужен VPS с Linux, Docker и Docker Compose (если обрабатываете данные граждан РФ, выбор страны сервера обсудите с юристом). Аренда: Timeweb Cloud по партнёрской ссылке https://timeweb.cloud/r/nf413716
ПОМЕТКА О ВОЗНАГРАЖДЕНИИ: ссылка партнёрская, автор канала получает вознаграждение, цена для вас от этого не растёт. Тарифы (по данным автора на момент записи от ~490 ₽ в месяц, не проверено) и бонус проверяйте на сайте.

ШАГ 2. ТУННЕЛЬ И БОТ
Создайте туннель в Cloudflare Zero Trust, маршрут вашего домена на http://n8n:5678, скопируйте токен в TUNNEL_TOKEN. В Telegram создайте бота у @BotFather и сохраните токен.

ШАГ 3. НАСТРОЙКИ
Скопируйте файлы на сервер, например в /opt/checkin. В папке:
  cp .env.example .env
  openssl rand -hex 32     (выполните дважды: для POSTGRES_PASSWORD и N8N_ENCRYPTION_KEY)
Впишите значения, домен HOST, папку сканов SCANS_DIR (на зашифрованном томе, права только для владельца) и токен туннеля. N8N_ENCRYPTION_KEY задайте один раз и никогда не меняйте.

ШАГ 4. ЗАПУСК
  docker compose up -d
  docker compose ps
Должны работать postgres, n8n и cloudflared. Если контейнер не стартует, смотрите docker compose logs. Откройте https://ВАШ_ДОМЕН и создайте администратора n8n.

ШАГ 5. СЦЕНАРИЙ
В n8n: Workflows, Import from file, checkin_workflow.json. Создайте учётные данные Telegram (токен бота) и PostgreSQL (хост postgres, база и пользователь из .env) и выберите их в узлах. В узле «Отправить код на замок» впишите адрес и токен API вашего замка. Активируйте сценарий и проверьте его на тестовом госте: фото паспорта, селфи, слово «согласен», получение кода.

ШАГ 6. БРОНЬ
Для каждого гостя заполните в таблице guests время выезда checkout_at (пин-код действует до него).

РЕЗЕРВНАЯ КОПИЯ (ОБЯЗАТЕЛЬНО, правило 3-2-1)
Запустите bash backup.sh: он делает дамп PostgreSQL и архив настроек. Сканы копируйте только на зашифрованные носители. 3 копии, 2 носителя, 1 вне сервера. Не удаляйте оригиналы, пока копия не проверена (восстановите её на тестовой машине).
